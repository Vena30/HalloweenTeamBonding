# Blackthorn Manor: Host-Controlled Multiplayer (Vercel + Neon)

A Next.js 15 multiplayer Halloween escape-room game. Built from the existing 10-room game, including its 10 original puzzles, pictures, team assignments, and 5/10-point scoring.

## Rules
- One **Game Master** controls Start, Open Answers, Close Room, Next Room, Finish Game, and Reset.
- 19 assigned participants log in individually using their **name and private six-digit PIN**.
- Participants see the same room but **cannot enter an answer** until the host clicks Open Answers.
- A server-side clock controls each room's answer window (default 5 minutes). The host can change this before opening.
- Correctness and arrival order are determined **inside one PostgreSQL transaction** using a game-row lock. Only the first correct submission from each team counts. The first two **different** teams to answer correctly qualify and **both get 5 points** (10 each in room 10).
- Once two teams qualify, the answer window automatically closes, but **only the host can move to the next room**.
- On expiry the server refuses further answers. The host closes the room and advances. If fewer than two teams qualified, points are awarded only after both different teams qualify; a single reserved slot does not count in the scoreboard.
- Host can inspect live submissions, server timestamps, which team responded, hints, and the scoring board.

## First-time setup
1. Create a new Neon PostgreSQL database and copy its **pooled connection string**.
2. In Neon SQL Editor, run `sql/schema.sql`.
3. Locally run `node scripts/seed.mjs`. The script creates `private/seed.sql` and `private/PARTICIPANT_PINS.txt` with random access PINs. **Do not commit these files to GitHub.** Run the generated `private/seed.sql` in Neon SQL Editor.
4. Make a private GitHub repository and upload the project (excluding `.env*`, `private/`, and `node_modules/`).
5. Import the repo into Vercel as a Next.js project.
6. Add Vercel environment variables `DATABASE_URL`, `HOST_PASSWORD`, `SESSION_SECRET` (use a long random secret of 64+ characters). See `.env.example`.
7. Deploy. Open `https://<your-deployment-domain>` on your host laptop. Select **Game Master**, log in with `HOST_PASSWORD`.
8. Share the same website URL with participants. Privately send each participant the PIN from `private/PARTICIPANT_PINS.txt`.
9. Test the host opening Room 1, two different players submitting the correct phrase, points awarding, and host advancing before your event.

## Development
`npm install` then create `.env.local` and run `npm run dev`.

## IMPORTANT: Deployment status
This folder is production-oriented source code, **not a live deployed game**. A Neon database, PIN seed, and Vercel deployment are still required. End-to-end tests with two real devices must be completed before using it for an event.

## Notes
- If a participant switches devices, they may log in again with the same name and PIN; server checks prevent the same name earning multiple qualifying responses.
- Refreshing the page does not reset timer or score; those are stored on the server.
- The participant interface never receives correct answers or full submission logs.
- Questions are shown to all players once the host starts the game; answer forms stay locked until the host opens them.
- Refresh for other devices is automatic through polling roughly every 1.6 seconds; very close races are settled by **server transaction order** rather than Zoom hand raises.
- The host may choose to disclose hints verbally through Zoom.
- Audio narration is generated by the browser speech engine; voices vary. Host should share tab audio in Zoom or Meet.
